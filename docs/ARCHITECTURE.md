# Architecture and desktop protocol

## Components and trust boundaries

- **Core domain:** parser, generator, models, audit, structured events, and conflict resolution.
- **Filesystem engine:** validates every destination before mutation, indexes source files, performs copy/move/cleanup, and emits events.
- **CLI adapter:** owns command-line defaults, timestamped output directories, audit output, and interactive duplicate selection.
- **Python sidecar:** one operation per process. stdin/stdout carry version 1 NDJSON; human diagnostics use stderr.
- **Electron main:** owns native dialogs and the child process. It validates renderer origin and request shape, denies untrusted navigation/windows/permissions, and forwards structured events.
- **Preload bridge:** exposes only directory selection and job start/cancel/conflict methods.
- **React renderer:** has no Node or filesystem access. It renders idle, running, conflict, success, error, and cancelled outcomes.

The renderer runs sandboxed with context isolation and Node integration disabled. A restrictive CSP allows only bundled assets (plus localhost connections for development). Remote fonts and runtime web dependencies are not used.

## NDJSON protocol version 1

The transport is newline-delimited UTF-8 JSON. One JSON object occupies one line. The initial line is a request. Every stdout line after it is an event or, during a conflict, the renderer's response. There is no envelope-level `version` field yet; incompatible protocol changes require a new sidecar/application version and this document must be updated.

### Generate request

```json
{"operation":"generate","source":"/path/to/folder","include_files":true,"max_depth":3,"indent_width":4}
```

`source` is required. `include_files`, `max_depth`, and `indent_width` are optional. `max_depth` must be positive and `indent_width` at least 2.

### Reconstruct request

```json
{"operation":"reconstruct","source":"/path/to/loose","destination":"/path/to/output","tree":"workspace/\n└── note.txt"}
```

Desktop reconstruction currently uses copy-only defaults. The sidecar also understands `move_files`, `overwrite`, `clean_relocated`, `dry_run`, and `indent_width`; those settings are engine capabilities, not current Canopy controls.

### Event shape

```json
{"kind":"progress","message":"Processed 2/5: note.txt","level":"info","current":2,"total":5,"data":{"path":"docs/note.txt"}}
```

Fields are `kind`, `message`, `level`, `current`, `total`, and `data`. Known kinds include `generated`, `start`, `directory`, `file`, `keep`, `skip`, `missing`, `delete`, `warning`, `conflict`, `progress`, `diagnostic`, `complete`, `cancelled`, and `error`. Consumers must tolerate new kinds and data keys.

A generated event carries `data.tree`. A conflict carries `data.path` and `data.candidates` with absolute source paths:

```json
{"kind":"conflict","message":"2 candidates","level":"warning","current":0,"total":0,"data":{"path":"note.txt","candidates":["/a/note.txt","/b/note.txt"]}}
```

The renderer answers on stdin with the exact candidate path, or `null` to skip:

```json
{"type":"resolve_conflict","choice":"/a/note.txt"}
```

### Completion, cancellation, and failure

- `complete` means the sidecar reached the end of the operation. Warnings or skipped/missing files may still have occurred.
- `error` is terminal. Spawn failure, malformed worker output, and premature worker exit are converted to error events by Electron.
- `cancelled` is generated by Electron after terminating the worker. `data.partial_results` is true: prior copies are not rolled back.
- The process should exit after `complete` or `error`. Electron treats an exit without a terminal event as failure.
- stdout is reserved for NDJSON. stderr is diagnostic text and must never be parsed as protocol output.

## Safety decisions

Parsing uses an explicit indentation unit and line-numbered errors. Copy is the default. Move, overwrite, and cleanup are opt-in CLI actions. Every destination is resolved and checked for containment before the first mutation. Existing target symlinks cannot redirect writes outside the selected root.
